**Where other tools fit.** *AtScale* and *Cube* are universal semantic layers that sit between the warehouse and many BI tools, with their own modelling language, caching and APIs; they make most sense when a company has several warehouses or many BI tools. *Atlan* (and similar catalogs such as Collibra or Alation) is a data catalog and governance layer: it documents and links metrics, owners and glossary terms across systems, but doesn't compute metrics. With Unity Catalog Metrics, the computing and much of the cataloguing happen in Databricks, so the question at work is usually "do we still need a separate semantic tool for the BI tools we keep?".

**OSI in one paragraph.** The Open Semantic Interchange is an industry effort, started in 2025 by Snowflake, Salesforce, dbt Labs and others and joined by Databricks, to agree a vendor-neutral format for semantic definitions (metrics, dimensions, relationships), so a metric defined once can move between warehouses, semantic layers and BI tools. It matters for lock-in: definitions are the hardest thing to migrate, so an open format makes choosing Unity Catalog Metrics less of a one-way door. Check its current status: it was early-stage when these labs were written.

**How HR data usually lands in Databricks.** Most companies pull from the HR system of record (Workday, SAP SuccessFactors, Oracle HCM) and the ATS (Greenhouse, Workday Recruiting). Databricks' managed path is **Lakeflow Connect**, which has a Workday reports connector; others use an ETL vendor or nightly file drops. Ask the rollout team which one your company uses, how often it runs, and whether HRBP assignments and effective-dated org data come across, because the Week 8 access model depends on them.
